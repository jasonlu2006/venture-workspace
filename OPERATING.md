# Venture Studio — Operating System

Mandate: build legitimate software / internet businesses that maximize
long-term expected profit via real customer value.

## Principles (from principal)
- Evidence over intuition.
- Cheap validation BEFORE implementation.
- Fast learning, kill weak ideas quickly, double down on proof.
- Low capital, useful products, recurring value, automation.
- HARD RULE: before anything is monetized or publicly released,
  create a HUMAN RELEASE REVIEW task. Do not cross that boundary alone.

## Process (per venture loop)
1. Hypothesis: a specific customer, pain, and willingness to pay.
2. Evidence pull: search demand, competition, market size, reachability.
3. Kill/score: use the scoring rubric. Kill fast if weak.
4. Cheap validation: landing/fake-door OR functional prototype.
   - No paid infra unless evidence justifies it.
5. Build MVP only after validation signal.
6. RELEASE GATE: when ready to deploy publicly or charge money,
   STOP and create a HUMAN RELEASE REVIEW task.

## Scoring rubric (1=poor .. 5=excellent)
- demand: search volume / forum complaints / market size
- competition: higher score = MORE room (lower saturation)
- reachable: can I find & contact the customer cheaply (online communities?)
- buildable: can I build a real MVP locally with available tooling
- recurring: sticky / recurring usage & revenue
- capital: low capital requirement (higher = cheaper)
- speed: time to first validation signal (higher = faster)

Average >= 4.0 => LEADER (build/validate now)
Average 3.0-3.9 => WATCH / DEFER
Average < 3.0 => KILL

## Workspace layout
- hypotheses/   : HYPOTHESES.md portfolio + scoring
- validation/   : landing pages, fake-door pages, survey copy
- products/     : real code (one dir per product)
- research/     : saved evidence notes

## Evidence log discipline
Record source URL + date for every demand/competition claim.
Prefer primary sources (forum threads, market reports) over listicles.
